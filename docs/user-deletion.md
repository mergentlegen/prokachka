# Удаление пользователя из CEO-панели

Для действующего проекта сначала примените `supabase/20261013-user-deletion.sql` в Supabase SQL Editor, затем выкладывайте код. `schema.sql` и `bootstrap.sql` повторно на действующем проекте не запускайте. Для проверки до выкладки используйте тестовую базу и резервную копию production.

Перед подтверждением CEO видит количество затрагиваемых заданий, программ, объявлений, ответов других участников и прямых подопечных. Удаление профиля и связанных публикаций выполняется одной транзакцией. Материалы с аудиторией удаляемого пользователя удаляются, а не становятся доступными всей команде. Чужие аккаунты и общие задания сохраняются; прямые подопечные переходят к родителю удалённого пользователя, а если родителя нет — становятся отдельными корнями. При любой ошибке SQL транзакция откатывается целиком.

Связанные Supabase Auth-учётки и PDF-файлы удаляются после транзакции. Их идентификаторы попадают в закрытые очереди с повторами; также продолжают работать существующие очереди аватаров и приветственных видео. Существующий таймер, запускающий `scripts/cleanup-welcome-videos.cjs` из текущего релиза, теперь обрабатывает все четыре очереди. Новую строку cron/systemd добавлять не нужно. Если таймер выключен, профиль исчезнет с сайта, но внешние файлы и Auth-учётка останутся до возобновления очистки.

Не удаляйте записи из очередей вручную и не меняйте аудиторию материалов на `NULL` для обхода ограничения FK: это откроет материалы всей команде. SQL-тест: `tests/user-deletion.sql` на одноразовой базе после `supabase/bootstrap.sql`; тест обработчика очереди: `node --test tests/user-deletion.test.cjs`.
