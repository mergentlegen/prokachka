# Фотографии в объявлениях

Примените `supabase/20261018-announcement-photos.sql` в Supabase SQL Editor до выкладки кода. Миграция идемпотентна: добавляет `announcements.photos`, закрытый bucket `announcement-photos` и очередь очистки удалённых файлов. Старые объявления остаются без фото и не меняются.

Наставник может добавить до 6 фотографий при создании или редактировании объявления. Исходники JPG, PNG, WebP, HEIC/HEIF до 25 МБ обрабатываются в браузере (включая поворот телефона), без обрезки и без EXIF/geolocation. На сервер поступает подготовленный JPG/WebP до 3 МБ. Сервер заново проверяет и кодирует две версии WebP: полную до 2048 пикселей и миниатюру до 640 пикселей, каждая не более 2 МБ. В ленте участник загружает миниатюры лениво, в галерее открывает полноразмерную версию. Bucket закрыт; подписанные ссылки выдаются только после обычной проверки видимости объявления по команде/ветке. Лимит подписанной ссылки — 24 часа; ссылки кешируются сервером для CDN.

Удаление фото, объявления, автора или команды ставит прежние файлы в очередь. Существующий таймер `prokachka-video-cleanup` запускает `scripts/cleanup-welcome-videos.cjs`, который теперь обрабатывает также очередь фотографий. При сбое удаления задача остаётся для повторной попытки. Если таймер на VPS не включён, требуется его включить; см. `scripts/prokachka-video-cleanup.service.example`.

Для пакетной загрузки до 6 фотографий серверный прокси (например, Nginx) должен принимать тело запроса до 20 МБ для `/api/announcements`. Если возникает HTTP 413, проверьте `client_max_body_size`, выполните `nginx -t` и только потом перезагрузите Nginx. Не меняйте этот лимит без необходимости для всего сайта.
