# Порядок заданий

В панели наставника: **Задания → Изменить порядок**. В одном окне показаны
опубликованные обычные задания и готовые игры. Можно перетаскивать за ручку,
нажимать стрелки или использовать ↑/↓ на клавиатуре, когда ручка в фокусе.
Изменения применяются только кнопкой «Сохранить порядок». «Отмена» их отбрасывает.

## Правила

- Закреплённые задания всегда выше остальных. Порядок меняется внутри каждой
  группы; само закрепление управляется прежними кнопками.
- Главный наставник задаёт порядок общих заданий команды. Наставник с правом
  публикации может задать свой порядок доступных ему заданий для своей ветки.
  Соседние ветки не затрагиваются. Вложенная ветка со своей настройкой сохраняет её.
- Участник наследует ближайшую настройку выше по своей сети. Сброс настройки
  ветки возвращает порядок вышестоящего наставника; сброс общего порядка —
  порядок по времени публикации и закрепления.
- Новые публикации добавляются в конец своей группы. Новое/повторное закрепление
  добавляется в конец закреплённых. Если сохранить новую расстановку, пока задание
  скрыто, после его возвращения оно добавится в конец группы.
- Готовая игра занимает один логический слот, даже если в ветке опубликована
  другая копия. Существующая попытка, ответы, мили и идентификатор задания участника
  не меняются.
- Просроченные и скрытые задания в окно перестановки не входят. Порядок шагов
  последовательных программ, дедлайны и доступность контента не изменяются.
- Если список или его порядок изменились во время редактирования, сохранение
  возвращает конфликт. «Обновить список» загружает актуальные данные и сбрасывает
  несохранённую расстановку.

## Установка

Для существующей базы применить **только**
`supabase/20261004-task-feed-order.sql` в Supabase SQL Editor, затем развернуть код.
`schema.sql` и `bootstrap.sql` повторно в рабочей базе не запускать.
Новая миграция допускает повторный запуск, не сбрасывает существующий порядок.
До её применения старая выдача заданий продолжает работать, но редактор недоступен.

Хранение — одна строка `task_feed_orders` на настройку команды/ветки, а не копии
заданий на каждого участника. Таблица и RPC закрыты от `anon`/`authenticated`.
API определяет пользователя из текущей сессии, SQL повторно проверяет его права,
проверяет состав обеих групп и сохраняет список атомарно с проверкой ревизии.
Одновременные сохранения сериализуются короткой блокировкой строки команды.
Доступность заданий по-прежнему проверяется существующим серверным фильтром;
сортировка не добавляет в выдачу недоступные задания.

## Проверки

- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
- `tests/task-feed-order.sql` — только на одноразовой тестовой PostgreSQL базе
  после fixtures и bootstrap; CI запускает автоматически.
- `npm run test:concurrency` — только с настроенной тестовой PostgreSQL базой.
- `tests/task-feed-order-ui.cjs` — отдельный локальный сервер на `127.0.0.1:3107`,
  Playwright + Edge, переменные `PROKACHKA_PLAYWRIGHT_MODULE` и
  `PROKACHKA_UI_ARTIFACT_DIR`. Все API перехватываются; реальные аккаунты не меняются.
