# Профили и аватарки

В профиле участника и наставника есть кнопка «Редактировать профиль». Она открывает имя, фамилию и фотографию. Фотографию можно добавить, изменить, удалить, приблизить и переместить перед сохранением. Почта показана только как информация об аккаунте; изменение способа регистрации к этой функции не привязано.

## Что сделать перед выкладкой

1. В Supabase → SQL Editor открыть содержимое `supabase/20261001-profile-avatars.sql` и выполнить целиком. Применять старые миграции или `schema.sql` повторно не нужно. Новую миграцию можно безопасно повторить. Она сама создаёт закрытый bucket `profile-avatars` и необходимые правила доступа.
2. После миграции отправить изменения в `main` обычным коммитом. CI соберёт приложение и зависимости обработки изображений; устанавливать дополнительные программы на Ubuntu не требуется.
3. Проверить, что ранее настроенный таймер очистки видео работает:

   ```bash
   systemctl is-active prokachka-video-cleanup.timer
   ```

   После обновления тот же таймер очищает и аватарки. Если он ещё не настроен, используйте примеры `scripts/prokachka-video-cleanup.service.example` и `scripts/prokachka-video-cleanup.timer.example`. Установить их из папки проекта:

   ```bash
   sudo install -m 644 scripts/prokachka-video-cleanup.service.example /etc/systemd/system/prokachka-video-cleanup.service
   sudo install -m 644 scripts/prokachka-video-cleanup.timer.example /etc/systemd/system/prokachka-video-cleanup.timer
   sudo systemctl daemon-reload
   sudo systemctl enable --now prokachka-video-cleanup.timer
   ```

   Путь к текущему релизу в примере: `/var/www/prokachka-deploy/current`. При другой установке исправьте `ExecStart` в service-файле. Для немедленной проверки очереди после замены фото:

   ```bash
   sudo systemctl start prokachka-video-cleanup.service
   sudo journalctl -u prokachka-video-cleanup.service -n 20 --no-pager
   ```

4. На сайте открыть профиль → «Редактировать профиль»: сохранить имя и фотографию, проверить рейтинг, затем заменить и удалить фотографию. После удаления отображаются инициалы. Проверьте профиль наставника кнопкой аватара в верхней панели или через «Мой профиль» в мобильном меню.

Предлагаемый коммит: `feat: add editable profiles and optimized private avatars`.

## Хранение и доставка

- Исходная фотография JPG/PNG/WebP/HEIC/HEIF до 25 МБ и 60 Мп остаётся в браузере. Это включает обычные снимки iPhone на 24/48 Мп. Тип проверяется по содержимому, а не только по MIME, который телефон иногда не заполняет.
- Браузер сначала пробует собственный декодер. Для HEIC/HEIF, которые он не открывает, по требованию загружается `heic-to/csp` — обработка идёт в локальном Web Worker, без отправки оригинала сторонним сервисам. CSP разрешает только локальные/Blob workers; `unsafe-eval` в production не добавляется. Для выбора кадра создаётся копия с длинной стороной до 2048 пикселей; затем отправляется выбранный квадрат 512 × 512.
- Сервер заново проверяет реальный формат и размеры, учитывает поворот, убирает EXIF/GPS и сохраняет квадратный WebP до 512 × 512. Жёсткий предел сохранённого файла — 256 КиБ; простые изображения существенно меньше.
- Перед сжатием проверяется реальная поддержка экспорта WebP браузером. Safari, который вместо WebP возвращает PNG, использует JPEG; сервер всё равно сохраняет WebP. Проверка выполняется один раз на маленьком canvas, качество при необходимости уменьшается до соблюдения лимита отправки 512 КиБ. Это не требует увеличивать bucket или разрешать большие файлы на сервере.
- База хранит путь к файлу и версию профиля. Исходники, история фотографий и копии для разных разделов не сохраняются.
- Закрытые файлы читаются по подписанным ссылкам. Ссылки выдаются после проверки доступа к соответствующему списку участников и действуют 24 часа. Это ссылки с доступом по владению: получатель может передать такую ссылку другому человеку до истечения её срока.
- Сервер переиспользует ссылки между разделами и пользователями, чтобы CDN мог отдавать один и тот же файл из кэша. Подпись выполняется пачками с ограничением параллельности; фотографии загружаются в браузере по мере появления на экране. Дополнительные платные преобразования изображений Supabase при просмотре не используются.
- Имя и фотография обновляются одной транзакцией с проверкой версии. При конфликте форма предлагает обновить данные, сохраняя введённые пользователем изменения.
- После замены, удаления фото, удаления пользователя или прерванной загрузки файл попадает в постоянную очередь очистки. Уже используемые аватарки защищены от удаления; временные сбои Storage повторяются с задержкой. Таймер обычно запускается каждые 10 минут. Заброшенная загрузка считается просроченной через час.

## Проверки

`npm test` включает проверки формата, размера, поворота и удаления метаданных изображения, доступа к редактированию своего профиля, конфликтов, подписанных ссылок и очистки. CI также применяет миграцию повторно и выполняет `tests/profile-avatars.sql` на одноразовой базе.

Проверка интерфейса с изолированными фикстурами: приложение на 3105, `node tests/helpers/ui-fixture-server.cjs` на 3106, затем `PROKACHKA_PLAYWRIGHT_MODULE` должен указывать на установленный пакет Playwright при запуске `node tests/profile-ui.test.cjs`. Фикстуры не пересылают API-запросы в настоящую базу.

Для проверки реального HEIF-декодирования задайте `PROKACHKA_HEIC_FIXTURE` — путь к тестовому `.heic`-файлу. Тест также проверяет JPEG 4284 × 5712 больше 5 МБ, уменьшение предпросмотра и неизменный лимит отправляемой аватарки. Изменение допустимых исходных фото не требует новой SQL-миграции или изменения лимитов bucket/Nginx.

`PROKACHKA_SIMULATE_SAFARI_ENCODER=1` запускает тот же браузерный тест с подменой неподдерживаемого экспорта WebP на PNG, как предусмотрено Canvas API. Проверяются JPEG-запрос с правильным расширением, маленький размер загрузки, сохранение и рейтинг. Это воспроизведение конкретного поведения encoder, а не полная замена проверки на физическом iPhone.

HEIF-декодер: [heic-to](https://github.com/hoppergee/heic-to), версия 1.5.2, LGPL-3.0. Используется неизменённая CSP-сборка; лицензия и исходники доступны в пакете и репозитории автора.
