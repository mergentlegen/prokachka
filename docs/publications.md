# Порядок публикаций и закрепление

В панели наставника «Программы» находятся сразу после «Заданий». Обычные задания и каталог готовых игр остаются в «Заданиях». Последовательные программы управляются отдельно: кнопка «Создать программу» открывает большой диалог, а нажатие на название опубликованной программы показывает её шаги с редактированием и PDF-файлами. В кабинете участника переключатель «Задания / Программы» сохранён.

## Порядок

- Сначала закреплённые публикации, затем остальные. В каждой группе — от старых к новым, с устойчивым порядком по ID при одинаковой дате.
- Новые задания, программы и объявления появляются внизу своей группы. Редактирование не меняет дату публикации.
- Можно закрепить несколько публикаций. После открепления публикация возвращается на своё место по дате.
- Закрепление программы передаётся её текущему шагу у участника. Шаги внутри программы по-прежнему идут по порядку прохождения.
- Готовые игры можно добавить, убрать из заданий и закрепить. Удаление результатов или начисленных миль при этом не выполняется.
- Закрепление не расширяет доступ: правила команды и ветки остаются прежними. Управлять может автор с действующим правом публикации или верхний наставник своей команды. Скрытые публикации не становятся видимыми от закрепления.

## Обновление действующей базы

Перед выкладкой кода выполните в Supabase SQL Editor **только** `supabase/20260927-publication-pins.sql`. Не запускайте заново `schema.sql` или весь `bootstrap.sql` на действующей базе.

Миграция добавляет `is_pinned` к трём таблицам и обновляет серверную функцию изменения программы. Существующие публикации, даты, задания, работы и мили сохраняются. Повторный запуск этой миграции безопасен: он не снимает уже поставленные закрепления. Если SQL завершился ошибкой, не выкладывайте код до её устранения.

В CI миграция проверяется на новой базе и повторным запуском. Проверки включают права автора/наставника, запрет чужой команды и отозванного доступа, сохранность шагов и даты публикации.
