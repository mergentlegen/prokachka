# Обновление Telegram и истории работ

## Что изменено

- Telegram связан с одним аккаунтом сайта. Привязка и использование токена выполняются атомарно; второй токен не может заменить уже привязанный Telegram.
- Кнопка отправки создаёт временную сессию на 15 минут, связанную с пользователем, Telegram и заданием. В базе хранится хеш токена. Старые ссылки `task_<id>` и ID задания в подписи больше не разрешают отправку.
- Работа появляется только после получения ответа ботом. Ошибочная попытка переключения аккаунта сбрасывает прежний выбор задания. Повторный webhook не создаёт дубль; отправленный ответ не перезаписывается. Новая попытка возможна после возврата на доработку.
- Основные наставники команды и проверяющие среди всех предков участника получают работы. Соседние ветки, другие команды и сам автор ответа исключены. Право публикации само по себе не даёт права проверки.
- Выдача прав создаёт уведомление. Выдача права проверки дополнительно ставит в очередь уже ожидающие работы всей ветки. Изменения через CEO-панель и переносы веток также учитываются триггерами базы.
- Перед доставкой повторно проверяются действующие права. Если Telegram ещё не привязан, уведомление ждёт привязки. При сбое сообщение остаётся в очереди с задержкой повторной попытки.
- Личная история отделена от очереди наставника, содержит названия завершённых шагов программ и все попытки доработки. Старые пустые записи со статусом `pending` скрыты, но не удалены. Старые оценки не пересчитываются автоматически.
- Проверка, начисление миль и открытие следующего шага программы выполняются одной транзакцией. Два наставника не могут перезаписать решение друг друга. Действия «Принять» и «Вернуть» из истории сохранены; версия записи защищает от одновременных изменений. Старую попытку нельзя переоценить после нового ответа, а шаг программы нельзя откатить, если уже отправлены работы следующих шагов.
- Исправлена изоляция команд в выборке работ. Документы скачиваются, а не исполняются как HTML сайта. Прямой доступ браузерных ролей Supabase к таблицам и служебным функциям закрыт; приложение работает через серверный `service_role`.

## Порядок выкладки

1. Сделать резервную копию базы. Проверить, что используется актуальная схема с миграциями иерархии, программ, Telegram и содержимого ответов.
2. На тестовой копии, затем на рабочей базе выполнить **`supabase/telegram-integrity-migration.sql` целиком**. Файл транзакционный и допускает повторный запуск. Он не удаляет пользователей, ответы или оценки. Если найдутся старые дубли Telegram ID, создание уникального индекса остановит миграцию — сначала нужно вручную разобраться с владельцами, не удалять привязки наугад.
3. Обновить код, установить зависимости и собрать приложение. Новые серверные методы требуют эту миграцию; без неё отправка будет закрыта, небезопасного запасного пути нет. Старые выбранные задания пользователям нужно открыть заново на сайте. Во время перехода лучше временно остановить приложение, чтобы старый обработчик не продолжал принимать ответы по прежним правилам.
4. Добавить в серверный `.env.local` отдельный случайный `TELEGRAM_DELIVERY_SECRET` длиной от 32 символов. Он не должен совпадать с токеном бота, webhook-secret или AUTH_SECRET. Не публиковать его в Git. Проверить `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `TELEGRAM_BOT_USERNAME`, `NEXT_PUBLIC_APP_URL=https://prokachka.kz`.
5. Перезапустить приложение. Webhook должен по-прежнему отправлять `X-Telegram-Bot-Api-Secret-Token`.
6. **Настроить регулярную обработку очереди.** После новых ответов, привязки и изменений прав обработка запускается автоматически, но для гарантированных повторных попыток после простоя нужен серверный таймер.

Пример строки в `crontab -e` пользователя, запускающего приложение (проверить путь `node` через `command -v node`):

```cron
* * * * * cd /var/www/prokachka && /usr/bin/node --env-file=.env.local scripts/deliver-telegram.cjs
```

Скрипт вызывает защищённый POST `/api/internal/telegram/deliver`; секрет передаётся в заголовке, не в URL. За один вызов обрабатывается до 10 уведомлений с ограничением времени. Для очень большой очереди можно запускать таймер чаще: задания захватываются с блокировкой, параллельные обработчики не берут одно задание одновременно.

Контроль очереди в SQL Editor (здесь только чтение):

```sql
select kind, count(*) as waiting, min(created_at) as oldest
from public.telegram_notification_jobs
where delivered_at is null and cancelled_at is null
group by kind;

select id, kind, attempts, available_at, last_error
from public.telegram_notification_jobs
where delivered_at is null and cancelled_at is null and last_error is not null
order by available_at;
```

Если Telegram недоступен или пользователь заблокировал бота, доставка откладывается; сама работа остаётся в панели. Уже отправленные сообщения нельзя отозвать сменой прав. Возможен редкий повтор Telegram-сообщения при аварии между его отправкой и записью результата в базу: Telegram не предоставляет ключ идемпотентности для отправки. Ответы и оценки в базе при этом не дублируются.

## Проверки

```sh
npm run lint
npm run test:backend
npm run test:mobile
npm run build
```

SQL-тесты запускать **только на отдельной локальной тестовой PostgreSQL**, не на production. Нужны роли `anon`, `authenticated`, `service_role` (последняя с BYPASSRLS), затем `schema.sql` и новая миграция.

```sh
psql -X -h 127.0.0.1 -p 55439 -U postgres -d postgres -v ON_ERROR_STOP=1 -f tests/telegram-integrity.sql
PROKACHKA_TEST_PG_PORT=55439 node --test tests/telegram-concurrency.test.cjs
```

`tests/telegram-integrity.sql` проверяет более 40 условий и откатывает фикстуры. Тест параллельных запросов оставляет изолированные фикстуры в временной базе. Переменная `PROKACHKA_TEST_PSQL` позволяет указать полный путь к `psql`.

После выкладки проверить двумя тестовыми аккаунтами: повторную привязку одного Telegram, попытку отправки из чужого аккаунта, текст/фото/видео, выдачу и отзыв прав, чужую ветку, собственную работу проверяющего и завершение шага программы. Реальную доставку через production-бота локальные тесты не заменяют.

Один ответ сейчас — одно сообщение: текст, фото, видео или документ, пояснение к файлу в подписи. Альбомы бот явно отклоняет и просит отправить отдельное сообщение; молча сохранять лишь первый элемент альбома он больше не будет.

Формат ссылки соответствует [официальным требованиям Telegram deep linking](https://core.telegram.org/bots/features#deep-linking): параметр `start` содержит допустимые символы и укладывается в 64 символа.
